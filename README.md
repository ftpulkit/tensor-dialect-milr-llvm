# Assignment 10 — Custom MLIR Dialect for Tensor Operations

> Compiler Design project — a custom MLIR dialect (`tensor_ext`) for
> multi‑dimensional array operations, together with a progressive lowering
> pass that rewrites it down to MLIR's standard `memref` dialect (and from
> there through the upstream pipeline all the way to LLVM).

---

## 1. What this project is

MLIR ("Multi‑Level IR") is the foundation compiler framework used by
TensorFlow, PyTorch (via Torch‑MLIR), IREE and others. Instead of one
fixed IR (the way classic LLVM has a single `.ll` IR), MLIR lets you
define **domain‑specific dialects** and **progressively lower** programs
through a chain of them. This project demonstrates exactly that workflow
on a small, self‑contained example:

| Stage | Dialect                         | Abstraction                          |
|-------|----------------------------------|--------------------------------------|
| 0     | **`tensor_ext`** (ours)         | High‑level: alloc / load / store / slice / transpose on whole arrays |
| 1     | `memref`, `scf`, `arith`, `func` | Buffers with explicit loops          |
| 2     | `memref`, `cf`, `arith`, `func`  | Explicit control‑flow (no `scf.for`) |
| 3     | `llvm` dialect                   | Ready for translation to LLVM IR     |

We provide:

1. A TableGen `.td` file defining the dialect, a custom `!tensor_ext.array<...>`
   type, and five ops: `alloc`, `load`, `store`, `slice`, `transpose`.
2. C++ implementations for op verifiers and the dialect glue.
3. A conversion pass `--convert-tensor-ext-to-memref` that uses MLIR's
   `DialectConversion` framework (TypeConverter + ConversionPatterns) to
   rewrite every op into `memref` + `scf` + `arith`.
4. A driver tool `tensor-opt` that registers our dialect alongside every
   upstream MLIR dialect/pass, so you can chain our pass with the standard
   lowerings all the way down to LLVM.
5. Seven `.mlir` test cases plus a hand‑written baseline for evaluation.

## 3. Prerequisites

The project has been developed and tested against MLIR/LLVM **18** on
Ubuntu **22.04 / 24.04**. Any recent Debian‑derived distro with the
`llvm-18-*` apt packages works.

### One‑time install

```bash
sudo apt update
sudo apt install -y \
    cmake ninja-build \
    clang-18 llvm-18-dev libmlir-18-dev mlir-18-tools
```

If you prefer a different version, set `LLVM_VERSION` before running
`./build.sh` — for example `LLVM_VERSION=17 ./build.sh`.

### Not on Ubuntu?

Building LLVM+MLIR from source also works; point `./build.sh` at your
install directory via:

```bash
MLIR_DIR=/path/to/llvm-install/lib/cmake/mlir \
LLVM_DIR=/path/to/llvm-install/lib/cmake/llvm \
./build.sh
```

## 4. How to build

```bash
git clone <this-repo>
cd tensor-dialect
./build.sh
```

`build.sh` will:

1. Verify that the required apt packages are installed (and print the
   exact `apt install` command if not).
2. Configure the project with CMake + Ninja against MLIR 18.
3. Build the `tensor-opt` binary into `./build/bin/tensor-opt`.

First build takes 1–3 minutes. Incremental rebuilds are near‑instant.

## 5. How to run

### Full demo + test suite

```bash
./run.sh
```

This prints a banner for each of the seven test cases, shows the input IR,
runs the appropriate `tensor-opt` command, shows the output IR, and checks
the exit code. At the end it prints a `SUMMARY` line with pass/fail
counts. See `EVALUATION.md` §4 for what each test demonstrates.

### Evaluation (numerical metrics)

```bash
./scripts/evaluation.sh
```

This produces a pretty‑printed report comparing our `tensor_ext` source
against hand‑written `memref` (SLOC + op count), counting ops at each
lowering stage, and timing each pass. The output is also saved to
`docs/evaluation_report.txt` for inclusion in the submission.

### Single file, by hand

```bash
# Just verify/parse:
./build/bin/tensor-opt testcases/01_parse.mlir

# Lower one file:
./build/bin/tensor-opt --convert-tensor-ext-to-memref testcases/02_lower.mlir

# Full pipeline to LLVM dialect:
./build/bin/tensor-opt \
    --convert-tensor-ext-to-memref \
    --convert-scf-to-cf \
    --convert-arith-to-llvm \
    --convert-func-to-llvm \
    --finalize-memref-to-llvm \
    --convert-cf-to-llvm \
    --reconcile-unrealized-casts \
    testcases/03_pipeline.mlir
```
